# Build a Matching Game in Godot

By the end of this course you will have built a working memory game — the kind
where you turn over two cards and try to find a pair — and you will be able to
fill it with **your own** words and pictures.

Here is what you are building:

![The finished game](images/finished-game.png)

The cards in that picture show Spanish words and their English translations, but
they could show anything: times tables, chemical symbols, French verbs, capital
cities. You will put your own content in during the last chapter.

## Why this game?

Because it is small enough to finish, and it quietly uses almost everything you
need to build your *own* projects later:

| Chapter | What you learn | Why it matters everywhere else |
|---|---|---|
| 1 | Scenes and nodes | How every Godot project is put together |
| 2 | Building a reusable scene | Make a thing once, use it a hundred times |
| 3 | Scripts and `_ready()` | Giving your objects behaviour |
| 4 | Signals | How parts of a game talk without getting tangled |
| 5 | Instancing and containers | Creating objects while the game runs |
| 6 | Game state and `await` | Rules, scores, and waiting without freezing |
| 7 | Reading files (CSV) | Getting real data into your game |
| 8 | `@export` and polish | Changing a game without editing code |

Eight short chapters. Each one ends with a game you can actually play, and a
few questions to check you have it.

## What you need

- **Godot 4.7** or newer — free from [godotengine.org](https://godotengine.org/download).
  No account, no install wizard on Windows; it is a single file you run.
- About **20 minutes per chapter**.
- No previous programming experience. If you have done a little Python or
  JavaScript, some of this will look familiar.

!!! tip "Prefer to watch?"
    Each chapter has a short companion video. If you get lost in the text,
    watch the video for that chapter first, then come back and follow along.

## How to use this course

Type the code in yourself. Do not copy and paste it.

That sounds like advice you can ignore, but typing is where the learning
happens — you will make small mistakes, read the error message, and fix them,
and *that* is the skill you are actually building. Copy-pasted code teaches you
nothing except that copying works.

Every chapter ends with the **full contents** of any file you changed, so if
something goes wrong you can compare yours against a known-good version.

!!! warning "If you get really stuck"
    The finished project lives in this repository. Look at it, compare it with
    yours, work out the difference. Starting over from the finished version is
    the last resort, not the first.

## A word about mistakes

You will hit errors. Everyone does — the difference between a beginner and an
experienced programmer is mostly that the experienced one has seen the error
before and is not scared of it.

When Godot shows you a red error message, **read it**. It usually tells you the
file, the line number, and roughly what went wrong. Nine times out of ten it is
a typo, a missing colon, or wrong indentation.
